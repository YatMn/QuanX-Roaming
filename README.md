# QuanX-Roaming

适合经常从香港、澳门往来中国内地或其他地区时使用的 Quantumult X 配置。

人在不同地区时，网络出口和 App 访问方式经常要跟着变：在内地，大部分国外网站和 App 通常需要走代理；在港澳，很多国外服务可以直连，可能只需要让 AI 这类服务单独走代理。

这份配置的核心思路很简单：用 `环境模式` 在 `【CN】中国策略` 和 `【HK】香港策略` 之间快速切换，同时保留 AI、常用 App、媒体、金融支付、广告拦截和 rewrite 增强等功能。

安装模板链接（下载后保存为本地 / iCloud 配置，再添加自己的节点）：

```text
https://raw.githubusercontent.com/YatMn/QuanX-Roaming/main/profiles/QuanX-Roaming.conf
```

## 功能概览

- `环境模式`：在内地常用的 `【CN】中国策略` 和港澳常用的 `【HK】香港策略` 之间切换。
- `AI`：默认在日本节点组内按可用性选择，也可以改选其他地区或手动固定节点。
- `Apple智能`：四个已确认的 Apple 智能云端入口默认跟随 `AI`，可以单独切换到 `苹果服务`。
- 稳定优先：地区组和 `自动选择` 不再按最低延迟选节点；仍提供可选的 `低延迟优先`。
- App 独立策略：Google、YouTube、Telegram、Netflix、TikTok、Instagram、Twitter 等可以单独切换。
- 媒体分流：包含 Netflix、YouTube、Spotify、哔哩哔哩、国际媒体等规则。
- `金融支付`：支付宝、微信支付、银联、银行、保险、12306 等可单独控制。
- 广告拦截与净化：包含广告规则、去开屏、YouTube/微博/高德/网易云/闲鱼/知乎/彩云天气等净化类 rewrite。
- 网页与功能增强：包含 Safari 搜索增强、豆瓣网页观影跳转、Google 重定向、小红书去水印、百度网盘净化/倍速、微信解锁被屏蔽链接等。
- 流媒体查询：包含流媒体解锁查询入口，方便检查节点支持情况。

## 稳定优先怎么用

| 场景 | 推荐选择 | 发生故障时 |
| --- | --- | --- |
| AI 日常使用 | `AI → 日本节点`；没有日本节点时，手动选一个实际可用的地区 | 在该组内按可用性选择；服务拒绝出口时仍需人工处理 |
| AI 想一直使用自己选的节点 | `AI → 手动固定`，再进入 `手动固定` 选具体节点 | 不自动备用，需要手动换节点 |
| Apple 智能云端功能 | 保持 `Apple智能 → AI`，复用当前 AI 出口 | 可单独改选 `苹果服务` 做路线对照；不会自动备用 |
| 普通常用 App | 保持 `环境模式`；在内地用中国策略，在港澳用香港策略 | 中国策略的 `自动选择` 可在全池重选，可能跨地区 |
| 普通 App 也希望同地区备用 | 在 `【CN】中国策略` 中选一次已有的地区组，例如香港节点 | 跟随该中国策略的 App 使用该组候选；不要选 `自动选择` 来限制地区 |
| 更在意测速结果 | 在 AI 或环境子策略中主动选 `低延迟优先` | 按测速选节点，可能改变地区或出口 |
| 金融支付 | 保持 `direct` | 先检查实际请求命中与对应 rewrite，不跟随全池自动切换 |

地区组保留原名称，改用 Quantumult X 的 `available` 策略：按客户端展开的候选顺序选首个可用节点；有流量触发且当前结果不可用时才发起检查。它不按延迟排名，但也不是永久粘住节点：订阅更新、手动测试、节点恢复后的选择需要在客户端核对。不能把候选顺序理解为已指定了某个主节点，亦不保证不中断或恒定 IP。详见[官方策略说明](https://raw.githubusercontent.com/crossutility/Quantumult-X/master/sample.conf)。

`日本节点`、`美国节点`等单一地区组将备用限制在该地区的名称匹配结果中；`欧洲节点`、`其他节点`和全池 `自动选择` 可能跨国家。分组依赖节点名称，不是出口所在地检测。没有该地区节点，或该组全部不可用时，不会替你跨地区或转直连，请手动选已有且可用的地区。

`手动固定` 是一个共用选择：多个 App 都选它时，会使用同一个选定节点。节点提供方也可能改变出口 IP。若需要每个 App 固定不同节点，应另行配置各自的选择，不能靠这个共用组实现。

首次设置后，用你常用的 AI 实际完成一次对话及常用功能，再保留该选择。绿色延迟只代表测试网址可达，不证明 AI 登录、对话、上传、语音或流媒体解锁成功。日常不需要反复测速寻找最低数字。

## Apple 智能怎么用

默认保持 `Apple智能 → AI` 即可。改变 `AI` 的选择，也会改变跟随它的 Apple 智能出口；切换 CN/HK 环境则不会改变独立的 AI 选择。若只想为这部分 Apple 流量换路线，可以改选 `Apple智能 → 苹果服务`，再查看 `苹果服务` 当前的选择（默认 `direct`）。这两个选项需要手动切换，不代表故障自动备用。

首批只加入四条精确主机规则：`apple-relay.cloudflare.com`、`apple-relay.fastly-edge.com`、`cp4.cloudflare.com` 和 `apple-relay.apple.com`。Apple 官方将它们列为 Private Cloud Compute 或 Apple Intelligence Extensions 入口；这不是完整 Siri 清单，也不保证功能解锁。[Apple 网络要求](https://support.apple.com/en-us/101555)

新规则不接管整个 Apple、iCloud 或 Cloudflare 域名，也不主动加入普通 Siri、搜索的共用入口。普通 Apple 服务的实际路径仍由原有已加载规则决定；现有 `Ai.yaml` 的设备内容尚待核对，不能据此承诺它们全部直连。四条本地规则随框架升级合并，不会随着上游名单变化自动扩大；其余远程规则保持自动更新。

使用前确认设备、系统、账号及所在地区支持目标功能。测试应触发实际云端请求，并查看是否命中 `Apple智能`；仅有端侧处理成功不能证明云端路径可用。当前配置仍丢弃 UDP 443/STUN/QUIC，文字、语音和不同智能功能要分别验证。若相关功能失败，先核对请求、当前规则内容及是否被 rewrite/MITM 影响，再做单项对照，不直接全局放开 UDP 或新增解密。

要撤回本轮 Apple 分流，在自己的可编辑配置中移除 `[filter_local]` 内 `# BEGIN Apple智能精准分流` 至 `# END Apple智能精准分流` 的规则块，再移除无引用的 `Apple智能` 策略。保留原有 AI、苹果服务及个人配置。改选 `苹果服务` 只是换路线，恢复备份也不一定恢复远程资源旧内容；完整恢复还需对应资源版本。

## 使用前准备

你需要先准备：

1. 已安装 Quantumult X 的 iPhone 或 iPad。
2. 一个可用的节点订阅，或你自己手动添加的节点。
3. 可以访问 GitHub Raw 链接的网络环境。

这份配置只提供规则、策略组和 rewrite，不提供节点。导入后还需要添加你自己的节点订阅。

## 导入配置

1. 打开 Quantumult X。
2. 进入配置管理页面。
3. 使用下面的链接下载或导入安装模板：

   ```text
   https://raw.githubusercontent.com/YatMn/QuanX-Roaming/main/profiles/QuanX-Roaming.conf
   ```

4. 将模板保存或复制成一份可编辑的本地 / iCloud 配置。不同客户端版本的按钮名称可能不同，以配置管理页面为准。
5. 切换到这份本地 / iCloud 配置，然后再添加节点。不要一直使用与 Raw 链接远程关联的完整配置。

项目此前记录过：远程关联的完整配置无法追加节点资源。如果添加订阅的入口不可用，先检查当前配置是否仍处于远程关联状态。

如果导入失败，先确认：

- 复制的是 Raw 链接，不是 GitHub 页面链接。
- 链接末尾是 `QuanX-Roaming.conf`。
- 当前网络可以访问 `raw.githubusercontent.com`。

## 添加节点

配置导入后，还需要添加节点：

1. 进入 Quantumult X 的节点、服务器或资源管理页面。
2. 添加你的节点订阅，或手动添加节点。
3. 更新节点资源。
4. 回到策略页，确认节点已经出现。

如果策略组里没有节点，通常是节点还没添加、订阅没有更新成功，或节点名称不适合自动归类。先确认节点本身能正常显示和使用。常见地区全名、代码和国旗可用于归类；订阅信息行和明确的内地节点名称会被排除。名称不符合时应检查分类规则，不要为了出现节点而关闭所有筛选。

## 日常使用

在中国内地：

1. 打开 Quantumult X 的策略页。
2. 找到 `环境模式`。
3. 切换到 `【CN】中国策略`。
4. Google、YouTube、Telegram、Netflix 等国外服务跟随 `环境模式` 走代理。
5. `金融支付` 建议优先保持 `direct`。
6. `AI` 保持已验证可用的独立地区或固定节点，不必随普通 App 改出口。

在香港、澳门或其他国外服务可直连的地区：

1. 打开 Quantumult X 的策略页。
2. 找到 `环境模式`。
3. 切换到 `【HK】香港策略`。
4. Google、YouTube、Telegram、Netflix 等常用国外服务可以跟随 `环境模式` 直连。
5. `AI` 保持已验证可用的独立地区或固定节点。
6. 如果某个媒体 App 需要指定地区，可以只切换对应 App 的策略。

只有当前选了 `环境模式` 的 App 会跟随切换。曾经为单个 App 手选 `direct` 或某地区后，如需恢复跟随，请把该 App 选回 `环境模式`。无需重置刻意保留的 AI 或媒体地区选择。

`兜底分流` 仅处理未匹配其他规则的流量，不是已命中 AI、Google 等策略后的故障备用。换它通常不能修复已经命中其他 App 策略的请求。

## 常见问题

### 导入后没有节点

正常。这份配置不包含节点，请先添加自己的节点订阅。

### AI 不能用

按现象处理，避免连续换很多节点：

1. 整个服务打不开：确认所选地区组有节点，检查该组连通性。若整组不可用，选择已有的备用地区；`手动固定` 模式需要自行更换具体节点。
2. 测速正常，但登录被拒、出现地区限制或某项 AI 功能失败：自动备用未必会触发。查看请求记录是否命中 `AI`，再用已验证可用的节点复测，不能把所有错误都归因于节点故障。
3. 对话文字正常，语音异常：另查 UDP 限制及相关请求；改成 `direct` 也不会自动解除全局 UDP 丢弃设置。

节点恢复、订阅更新或手动测速后，复核实际选中的节点。首次使用前先确定一条可用路径，再安排备用。

### 支付或银行 App 异常

进入 `金融支付` 策略组，先尝试 `direct`。如果仍然异常，再检查相关 rewrite。

### 某个 App 登录、播放或跳转异常

整个服务打不开时先检查出口；只有登录、播放、地图、网盘或跳转异常时，临时关闭该 App 对应的 rewrite，再复测。每次只改一项并记录原选择；确认无关就恢复，避免同时更换节点、DNS 和多个 rewrite 后无法定位原因。

广告规则的开关与 rewrite 是两件事：`广告拦截 → direct` 不会关闭 rewrite。现有 rewrite 仍保留原启用状态。

### App 按钮与实际请求不一致

查看 Quantumult X 的请求记录，确认目标域名、命中的规则和最终策略。模板已将 YouTube 特定规则放到 Google 通用资源前，但实际结果仍受客户端加载的资源内容影响。

现有 `Google Voice` 远程列表目前只含 `lens.l.google.com`，不能仅凭名称判定它属于 Google Lens。本次保留该资源并放到 Google 通用规则前，同时给 `voice.google.com`、`voice.telephony.goog` 两个已知入口配置美国出口。这不代表完整登录、媒体与通话流量都已覆盖；使用 Voice 时仍需检查真实请求。[旧规则内容](https://raw.githubusercontent.com/ddgksf2013/Filter/master/GoogleVoice.list)、[Google Voice 网络要求](https://knowledge.workspace.google.com/admin/voice/voice-connectivity-requirements)。

## 已有用户升级

2026-09-20 是一次框架更新：只刷新远程规则不会获得新的策略类型。

1. 备份当前使用的完整本地 / iCloud 配置，保留自己的订阅与证书。
2. 对照新版模板，将 `[policy]` 中的策略定义更新到自己的可编辑配置；保留私有节点区块、DNS、MITM 及个人其他设置。地区策略名称不变，新增 `低延迟优先`、`手动固定`、`Apple智能`。若有自定义策略，请逐项合并，不整段覆盖。
3. 对照更新 `[filter_remote]` 中 YouTube、Google Voice 特定资源位于 Google 通用资源之前的顺序，并在 `[filter_local]` 的宽泛规则前加入两个 Voice 入口规则。
4. 将新版 `[filter_local]` 内有 BEGIN/END 标记的 Apple 智能四条规则块合并到自己的本地规则前部，并确认第 2 步已加入对应策略。只刷新远程资源不会得到这四条本地规则。
5. 检查旧选择是否保留：AI 默认日本、金融直连、普通 App 跟随环境，新增的 `Apple智能` 默认跟随 `AI`；若想继续按最低延迟选择，主动改选 `低延迟优先`。
6. 按下面的更新流程处理资源，并完成手机验证。失败时恢复对应配置或资源版本，不要反复导入覆盖订阅。

仓库 Raw 链接只包含已发布版本；本地修改在发布前不会出现在该链接中。更换整份模板时，它不包含你的订阅和证书，需要从自己的备份中保留这些内容。

## 资源更新与恢复

日常继续沿用现有自动更新入口和周期。需要手动升级或排查时，先分清改的是哪一层：

| 更新内容 | 会改变什么 | 恢复依据 |
| --- | --- | --- |
| 配置框架 | 策略组、本地规则、资源地址或顺序 | 修改前的可编辑配置备份 |
| 资源解析器 | 将资源转换为 Quantumult X 语法的方式 | 之前在设备上验收过的确定提交或已保存内容 |
| 远程规则 / rewrite | 域名、重写和引用脚本 | 该资源的确定提交或原始内容快照；引用脚本若也变化，需分别恢复 |

模板已引用 KOP-XIAO 的自动更新地址。9 月 16–18 日的修复涉及转换和误报，Hysteria2 的变化是改善“不支持”的识别，并非新增协议支持。URL 没变不能证明设备加载了新版，刷新规则也不保证解析器随之重新下载。[解析器更新记录](https://github.com/KOP-XIAO/QuantumultX/commits/master/Scripts/resource-parser.js)

更新前保存能取得的解析器及关键资源内容，记录客户端版本和当前可用状态。按当前客户端实际入口更新解析器，再重新处理依赖它的 `Ai-All-In-One`、全球加速、国内网站等资源；用到知乎/百度网盘相关 rewrite 时也分别复测。确认转换输出有效、关键规则保留，再保持原出口验证常用功能。Google、YouTube 等未启用解析器的原生资源不因此直接获得修复。

只有实际加载内容能对应到具体版本，且功能实测通过，才能把它记录为可回退版本。版本不可见时，记录“业务通过、解析器版本未知”；本次公开候选提交 `38a6fe02eb7cc67efd26a8f3c618bd031f1885b4` 尚未在本项目设备验收，不能直接称为已知可用版本。

解析器回归时，可临时将 `resource_parser_url` 指向已验收提交的固定地址，再重新处理受影响资源；恢复后再决定何时回到自动更新。固定地址形式是 `https://raw.githubusercontent.com/KOP-XIAO/QuantumultX/<已验收提交>/Scripts/resource-parser.js`，其中占位部分需替换为真实提交。若只是一条 rewrite 出错，先停用该项做对照。没有旧内容或确定版本时，不能保证精确回退；旧 `.conf` 中的浮动 URL 仍可能下载新版内容。

## 验证

公开模板可在本地检查：

```bash
python3 scripts/validate-profile.py
```

检查策略引用、循环、稳定选择方式、合成节点名称分类、Apple 智能四条精确规则及可整体移除的范围、YouTube 资源顺序、已知 Voice 入口、金融与环境默认值，以及公开模板中是否混入节点或证书。正则检查使用 Python 的公共语法子集；这不是 Quantumult X 运行测试，也不测试真实订阅或远程资源下载。

修改模板或校验器后，可运行 `python3 scripts/test-profile-validation.py`，用临时副本验证缺失主机、错误后缀、共用入口误入、远程范围扩张（含参数空格）和不完整撤回等 13 类错误会被拒绝。它不会访问网络或修改实际配置。

安装或升级后仍需在手机验证：

| 验证场景 | 应检查的结果 |
| --- | --- |
| 导入和节点分类 | 客户端无配置错误，所需地区组有实际节点；核对候选与当前出口 |
| AI 连续对话及常用功能 | 能登录、连续使用；请求命中 AI；不以测速绿色代替业务成功 |
| Apple 智能云端功能 | 有真实云端请求并命中 `Apple智能 → AI → 当前出口`；核对设备分流匹配优化/插入资源设置，切换到苹果服务后路径符合选择 |
